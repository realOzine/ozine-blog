# 决策与取舍记录

[`plan.md`](plan.md) 是最初的规划。本文件记录实现首版时做出的每一个选择：选了什么、放弃了什么、代价是什么。
标「待确认」的条目是我替你做的暂定选择，改起来成本都不高。

## 0．只读检查真实库后的发现

实现前按计划第一步只读检查了 `~/Documents/Obsidian/ozine`，有三点与规划的假设不一致：

| 发现 | 影响 |
| --- | --- |
| `40 blog` 里还没有真实文章，只有 Quartz 的占位 `index.md` 和空的 `drafts/`、`published/` | 无法用真实文章验证，改用仓库内的模拟库（D1） |
| 附件目录是 `90 system/attachments`，在 `40 blog` **之外** | 只靠 `content` 软链接读不到图片（D5） |
| 现有笔记的图片用标准 Markdown 相对路径 `![](../../90%20system/attachments/x.webp)`，不是 `![[图片]]` | 两种写法都要支持（D6） |

## 1．内容来源与测试

### D1 测试样本放在仓库的 `fixtures/vault/`，不写进 Obsidian 库

- **选择**：在仓库内模拟一个最小的库（博客目录、库外附件目录、库外私密笔记）；错误样本在测试里临时生成。
- **放弃**：往真实库里写 mock 文章。
- **得**：不改动你的笔记；克隆仓库即可跑通测试。
- **失**：样本不是你的真实写作习惯，真实文章里可能有样本没覆盖的语法；软链接路径另由一条测试单独验证。真实文章出现后应先跑 `npm run release -- --dry-run`。

### D2 `content` 软链接指向 `40 blog`（沿用旧 Quartz 项目的指向）

- 已建立，Git 忽略。`40 blog` 下的 `drafts/`、`published/` 子目录只是你的组织方式，程序**不看目录名**，只看 `status`。
- **失**：把文章放进 `published/` 目录不会让它发布，可能与直觉不符。

### D3 缺少 `status` 的文件阻止发布，不设忽略名单（待确认）

- **选择**：严格按规划「缺失或非法状态阻止发布」，内容目录下每个 `.md` 都必须有合法 `status`。
- **放弃**：自动跳过没有 frontmatter 的文件，或维护忽略列表。
- **得**：不会因为漏写字段而悄悄漏发或误发。
- **失**：**当前真实库会被 `40 blog/index.md`（Quartz 占位页）拦下**。我没有改动你的笔记，需要你删除它或加上 `status: draft`。以后想在博客目录放非文章笔记（选题清单等）也都要写 `status: draft`。

## 2．导出规则

### D4 双链、图片在导出时改写；Callout 留到构建时渲染

- **选择**：导出脚本把 `[[双链]]` 改写成 `[标题](/posts/slug/)`、把图片改写成 `![](../assets/x.png)`、删除 `%%注释%%`；`> [!note]` 原样保留，由 Astro 侧的插件渲染。
- **理由**：双链解析需要「文件名 → slug」的全库索引，只有本机有；公开副本必须自洽，Vercel 才能脱离 Obsidian 构建。Callout 本身是合法的 Markdown 引用块，不依赖索引，留在构建侧可以随时改样式而不必重新导出。
- **失**：公开副本不再是原稿的逐字拷贝；Obsidian 语法的处理分散在两处（`scripts/lib/export.ts` 与 `src/plugins/callout.ts`）。

### D5 附件：从软链接的真实路径向上找库根目录，不增加第二个软链接

- **选择**：对 `content` 取真实路径，向上找到含 `.obsidian` 的目录作为库根，再读 `.obsidian/app.json` 的 `attachmentFolderPath`。查找顺序：相对原稿 → 相对库根 → 按文件名在附件目录和博客目录中查找。
- **放弃**：再建一个 `attachments` 软链接；或把附件搬进 `40 blog`。
- **得**：零配置，不改变你现在的附件习惯，原稿里的 `../../90 system/...` 相对路径可以直接解析。
- **失**：程序会读博客目录之外的位置。为此加了三道限制：只导出被已发布文章**实际引用**的文件；只允许图片扩展名（png/jpg/jpeg/gif/webp/svg/avif），笔记无法伪装成附件；真实路径必须在库内。PDF、音视频等附件首版不支持。

### D6 两种图片写法都支持；`![[图.png|300]]` 的尺寸被忽略

- 图片交给 Astro 的图片管线（相对路径 `../assets/`），自动转 WebP、写入宽高、缺图时构建失败。
- **失**：Markdown 语法无法携带宽度，首版不保留 Obsidian 的尺寸设置；非数字的别名会作为替代文字。附件文件名中的空格和括号会被替换为 `-`；不同目录下的同名附件，后者文件名追加内容哈希。

### D7 用逐行状态机 + 正则转换正文，不走 Markdown AST

- **得**：实现短、无额外依赖，未触及的文本逐字保留，报错能给出原稿行号。代码块和行内代码会被跳过。
- **失**：对极端写法不如 AST 严谨（例如缩进代码块里的 `[[...]]` 仍会被当作双链；跨行的行内代码）。真实文章碰到时再考虑换 AST。

### D8 双链的解析与显示

- 不带路径按文件名匹配，带路径按路径后缀匹配，不区分大小写；范围**仅限博客目录**。
- 指向库内其它目录（如 `30 domain`）的双链按「失效」报错，不会自动公开目标，也不会静默降级成纯文本。**失**：文章里引用自己的知识笔记时必须手动去掉或改写。
- 未写别名时，显示文字用目标文章的 `title` 而不是文件名（文件名是私有的组织方式）。**失**：与 Obsidian 里看到的文字可能不同。
- 标题锚点用 `github-slugger` 计算，与 Astro 生成标题 id 的算法一致，并校验标题确实存在。标题里含复杂行内格式时可能算不准（会报「找不到标题」而不是生成坏链接）。
- 不支持：块引用 `[[x#^id]]`、笔记嵌入 `![[笔记]]`（规划已排除）、指向笔记的 Markdown 链接 `[x](y.md)`，三者都明确报错。
- 链接写成绝对路径 `/posts/slug/`。**失**：站点必须部署在域名根路径，不能放在子路径下。

### D9 公开副本的 frontmatter 只保留白名单字段

- 只输出 `title`、`date`、`updated`、`tags`、`description`；`slug` 体现在文件名上，`status` 及其它 Obsidian 属性不输出。
- **得**：私有属性不会随文章进入公开仓库。**失**：以后新增公开字段要同时改导出脚本和 `src/content.config.ts`。

### D10 metadata 细则（待确认）

- 字段与状态名沿用规划的建议值。`draft` / `withdrawn` 只要求 `status` 合法，其余字段可以不全；`published` 必须有 `title`、`slug`、`date`。
- 新增两个可选字段：`updated`（更新日期）、`redirect_from`（见 D12）。
- `tags` 不允许空格、`/`、`#`：首版不支持 Obsidian 嵌套标签。大小写不同的标签（`Go` / `go`）归为同一个，网址用小写。**失**：标签网址可能是中文（`/tags/写作/`），浏览器可用但复制出来是百分号编码。

## 3．发布

### D11 `published/` 每次整体重建（镜像），而不是增量更新

- **得**：撤回、改回草稿、删除原稿、不再被引用的附件，都会自动从公开副本消失，逻辑只有一条。
- **失**：`draft` 与 `withdrawn` 的实际效果相同，区别只在语义；`published/` 里不能放手工维护的文件。撤回不会抹去 Git 历史（规划已说明）。

### D12 改 `slug` 的重定向靠手写 `redirect_from`，不自动检测

- **选择**：在文章里写 `redirect_from: 旧slug`，导出生成 `published/redirects.json`，Astro 据此生成跳转页。
- **放弃**：自动发现 slug 变化——那需要给每篇文章一个额外的稳定 ID。
- **失**：改 slug 时忘了写 `redirect_from`，旧地址直接 404，程序不会提醒。跳转是静态的 meta refresh 页面而非 HTTP 301（静态输出的限制；要 301 需改用 Vercel 适配器或 `vercel.json`）。

### D13 发布命令叫 `npm run release`

- `npm publish` 是 npm 的内置命令（发包到 npm 仓库），脚本若命名为 `publish` 还会被当作生命周期钩子，容易误触，所以避开。

### D14 发布命令只提交 `published/`，站点代码要自己提交

- 流程：检查 Git → 导出到 `.publish-tmp/` → 用临时副本构建 → 替换 `published/` → `git commit -- published` → `git push`。前三步任何失败都不会改动 `published/`、不提交、不推送。
- 暂存区有其它变更时直接停止；工作区有其它未提交变更时只提示。
- **失**：`git push` 会连同你本地尚未推送的其它提交一起推上去；推送失败时提交留在本地，需手动处理后再推。

### D15 只报告「推送成功」，不核实 Vercel 部署

- 本机没有 `vercel`、`gh` CLI，也还没有 Vercel 项目，无法查询部署结果。命令明确输出「部署状态未核实」。
- **后续**：项目建好后可用 Vercel API 轮询部署状态，补上「上线完成」的报告。

### D16 脚本用 Node 原生运行 TypeScript，不引入 tsx 等运行器

- **得**：少一个依赖。**失**：本机需要 Node ≥ 22.18（当前 24）；脚本里不能用 enum 等需要转译的语法。Vercel 只执行 `astro build`，不受影响。

## 4．站点

### D17 沿用 Astro 7 默认的 Sätteri 处理器，Callout 用自写的 hast 插件

- **背景**：Astro 7 的默认 Markdown 处理器从 remark/rehype 换成了原生的 Sätteri，remark 生态的现成 Callout 插件不能直接用。
- **放弃**：安装 `@astrojs/markdown-remark` 换回 unified 管线 + 现成插件。
- **得**：跟随默认路线，约 70 行插件，没有额外的运行时依赖。**失**：Sätteri 生态新、资料少；Callout 标题只支持纯文本；图标未做，只用颜色区分类型。

### D18 样式：Tailwind 4 + `@tailwindcss/typography`

- 正文排版用官方 typography 插件，而不是手写全部正文样式。**失**：默认风格偏英文排版，中文只做了行高和字体栈的调整。
- 深色模式跟随系统，没有手动切换按钮，全站零客户端 JavaScript。**失**：读者不能自行切换。
- 字体用系统字体栈，不加载 Web 字体：快，但不同系统观感不一致。
- 代码高亮用 Astro 内置的 Shiki，`github-light` / `github-dark` 双主题。

### D19 页面内容（待确认）

- 站点名暂用「Ozine」，简介、首页文案、关于页正文都是**占位内容**，集中在 `src/site.config.ts` 和 `src/pages/about.astro`。
- 首页：一句简介 + 最近 5 篇文章。
- 关于页正文直接写在 `about.astro`，不读取 Obsidian 的 `about.md`。**得**：导出管线不需要为单页开特例。**失**：改关于页要改代码并手动提交，而不是在 Obsidian 里写。
- 在规划的四个页面之外增加了 `/tags/` 和 `/tags/{标签}/`，用于「标签浏览」；导航栏保持规划的三项，标签入口放在文章列表页顶部。
- 文章目录只列二、三级标题：桌面端在右侧固定，手机端折叠在正文上方。

### D20 未配置 `site` 网址，未做 RSS / sitemap / Open Graph

- 域名未定，且这些不在首版范围内。定下域名后在 `astro.config.mjs` 加 `site`。

### D21 TypeScript 固定在 6.x

- 最新的 TypeScript 7 与 `@astrojs/check` 的 peer 依赖（`^5 || ^6`）冲突。
