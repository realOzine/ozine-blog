# 个人博客项目目标规划书

## 1．项目目标

从空项目开始，使用 **Astro + TypeScript + Tailwind CSS** 开发轻量、可控的个人博客，在实现过程中学习内容处理、静态页面生成和自动部署。

继续使用现有 Obsidian 写作。博客项目通过软链接读取文章，根据 Markdown metadata 筛选公开内容；手动执行发布命令后，将内容推送至公开 GitHub 仓库，由 Vercel 自动构建部署。

## 2．已确认的技术与工作方式

| 项目           | 决定                                   |
| -------------- | -------------------------------------- |
| 页面与静态生成 | Astro                                  |
| 开发语言       | TypeScript                             |
| 样式           | Tailwind CSS                           |
| 内容格式       | Markdown + YAML frontmatter            |
| 写作工具       | 现有 Obsidian                          |
| 本地内容入口   | `content` 软链接指向 Obsidian 博客目录 |
| 版本管理       | 公开 GitHub 仓库                       |
| 发布方式       | 手动执行一次发布命令                   |
| 部署平台       | Vercel，随 GitHub 更新自动部署         |

Obsidian 原稿是唯一写作源，公开仓库中的内容副本由程序维护。

## 3．页面与路径

已确认包含首页、文章、关于三个主要入口，顶部导航为：**首页 · 文章 · 关于**。

| 页面     | 路径             | 内容范围                                 |
| -------- | ---------------- | ---------------------------------------- |
| 首页     | `/`              | 博客入口；个人简介、近期文章等为建议内容 |
| 文章列表 | `/posts/`        | 展示已发布文章                           |
| 文章详情 | `/posts/{slug}/` | 正文、metadata 与文章目录                |
| 关于     | `/about/`        | 个人介绍；具体内容待确定                 |

Astro 页面结构：

```text
src/pages/
├── index.astro
├── about.astro
└── posts/
    ├── index.astro
    └── [slug].astro
```

关于页的布局由 Astro 管理。正文直接写在页面中，还是读取 Obsidian 中的独立 `about.md`，留待实现前确定。

## 4．首版功能范围

首版包含：

- 首页、文章列表、文章详情、关于页。
- 标签浏览、文章目录、代码高亮与基础响应式排版。
- 标准 Markdown 与图片。
- Obsidian `[[双链]]`、`![[图片]]`、Callout 提示块。
- metadata 校验、状态筛选、附件导出。
- 发布命令串联校验、导出、构建检查、提交和推送。

暂不纳入首版：搜索、评论、反向链接、笔记嵌入、关系图谱、Obsidian 发布按钮。是否增加，由后续需求决定。

## 5．文章身份与 metadata

采用前文建议的路径设计作为暂定实现规则：**原稿路径用于组织笔记，`slug` 用于确定公开网址。**

```text
Obsidian：40 blog/Go/理解接口.md
    ↓ 软链接读取
本地项目：content/Go/理解接口.md
    ↓ 导出
公开副本：published/posts/go-interfaces.md
    ↓ 页面生成
网站地址：/posts/go-interfaces/
```

移动原稿或修改标题时，只要 `slug` 不变，公开网址就保持不变。

建议的 metadata：

```yaml
---
title: 理解 Go 的接口
slug: go-interfaces
status: draft
date: 2026-09-29
tags:
  - Go
description: 从行为约束理解接口。
---
```

字段与状态名称尚未逐项确认，暂按以下规则设计：

| 字段          | 建议规则                                     |
| ------------- | -------------------------------------------- |
| `title`       | 页面标题，发布时必填                         |
| `slug`        | 全站唯一；小写英文、数字、连字符；发布时必填 |
| `status`      | 显式控制发布状态                             |
| `date`        | 文章发布日期，用于排序                       |
| `tags`        | 分类标签，可选                               |
| `description` | 文章摘要，可选                               |

| 状态        | 发布时的行为           |
| ----------- | ---------------------- |
| `draft`     | 不导出                 |
| `published` | 导出文章及必要附件     |
| `withdrawn` | 移除当前公开副本和页面 |

缺失或非法状态阻止发布。已发布文章修改 `slug` 时，应处理旧地址重定向；撤回不会抹去公开 Git 历史。

## 6．内容处理与发布架构

```text
Obsidian 博客目录
    ↓ content 软链接
读取原稿、校验 metadata、建立文章索引
    ↓
筛选公开文章，解析双链、图片与 Callout
    ↓
生成公开文章及附件副本
    ↓
Astro + Tailwind 构建网站并检查
    ↓
提交并推送 GitHub
    ↓
Vercel 自动构建部署
```

软链接只用于本地读取，不提交为云端内容来源。GitHub 保存实际导出的文件，Vercel 可以独立构建，无需访问本机 Obsidian。

建议的项目结构：

```text
blog/
├── content -> Obsidian 博客目录     # Git 忽略
├── published/
│   ├── posts/                     # 公开文章副本
│   └── assets/                    # 所需附件
├── scripts/                       # 导出与发布入口
├── src/
│   ├── content.config.ts
│   ├── pages/
│   ├── layouts/
│   ├── components/
│   └── styles/
└── astro.config.mjs
```

目录按实际需要建立，不提前增加插件系统、数据库或通用 CMS 抽象。

### 链接与附件规则

- 双链先定位原稿，再读取目标文章的 `slug`，转换为网站地址。
- 建议首版支持文章名、显示别名和标题锚点。
- 重名、失效引用、指向未发布文章的链接应明确报错，不自动公开目标。
- 只导出公开文章实际引用的附件，并保证导出后的路径可正确解析。
- 笔记内容不能作为附件绕过状态筛选。
- 首页、列表、标签和详情页共用同一套公开文章筛选规则。

### 发布命令行为

1. 读取并校验内容，在临时目录生成发布副本。
2. 检查链接、附件和重复 `slug`，完成网站构建。
3. 检查通过后更新公开副本，清除已撤回文章的旧文件。
4. 仅提交明确的发布变更并推送；遇到冲突或推送失败时停止并说明原因。

“推送成功”与“部署成功”分别报告；只有核实 Vercel 结果后，才报告上线完成。

## 7．实施阶段

| 阶段     | 行动                                                   | 可检查的产出                                 |
| -------- | ------------------------------------------------------ | -------------------------------------------- |
| 内容验证 | 检查真实文章、图片路径和常用语法，验证软链接读取与导出 | 含双链、图片、Callout 的公开副本，草稿未导出 |
| 页面实现 | 完成三个主要入口、文章详情及正文排版                   | 可本地浏览和静态构建的网站                   |
| 发布实现 | 串联校验、导出、构建、提交与推送                       | 可重复执行的发布命令，失败时不推送           |
| 部署验证 | 连接 GitHub 与 Vercel，验证新增、修改、撤回            | 可访问的网站及完整发布证据                   |

优先验证内容链路，再扩展页面和发布能力。工期与预算尚未确定。

## 8．首版验收标准

- `/`、`/posts/`、`/about/` 及文章详情页可以正常访问。
- 在现有 Obsidian 中写作，无需手动维护第二份文章。
- 双链、图片、Callout、代码块与目录正确呈现。
- 草稿及无关附件不进入公开仓库和网站产物。
- 原稿移动或标题修改后，保持 `slug` 可以保持网址不变。
- 新增、更新、撤回文章可以通过发布命令完成。
- 撤回后，当前页面及列表、标签等入口同步更新。
- 字段错误、重复 `slug`、缺失附件与链接歧义能定位到具体文件。
- 仅克隆 GitHub 仓库，无需原始 Obsidian 库，也能构建网站。
- 页面在桌面与手机宽度下具有可用的阅读体验。

上述标准为计划中的验证要求，尚未实际测试。
