# 视觉设计

本文档说明站点的视觉设计：气质、颜色、字体、角色图，以及它们在代码里的位置。改样式前先读这里；改了设计就同步更新这里。

相关文档：[`architecture.md`](architecture.md)（文件职责）、[`decisions.md`](decisions.md)（每个选择的取舍，设计相关的是 D24–D32）。

## 1．气质

**首要原则是阅读舒适。** 任何设计上的取舍——颜色、字体、动效、装饰——和阅读舒适冲突时，都让位于它。

五个关键词：**冷静、忧郁、内心活跃、耐读、舒适**，整体带紫色的气质。

落到页面上是一条原则：**墨色与留白做主体，紫色只做点缀**。站点的角色图本身就是这个比例——黑发黑裙、白衬衫，紫色只出现在挑染、瞳孔和缎带上。

| 关键词 | 做法 |
| --- | --- |
| 冷静、忧郁 | 中性色是带一点紫调的冷灰，饱和度很低；整站不用暖色，唯一的例外是 Warning 提示块。 |
| 内心活跃 | 紫色只在少数位置出现：链接、选中的文字、星点、列表圆点、引用竖线。另有一组克制的动效（第 6 节）。 |
| 耐读、舒适 | 背景不用纯白，正文不用纯黑；暗色用深紫灰而不是纯黑；正文行高 1.85。 |

## 2．颜色

所有颜色都是语义 token，定义在 `src/styles/global.css` 的 `@theme` 里，写成 `light-dark(亮色, 暗色)`，跟随系统明暗（站点没有手动切换开关）。

**规则：组件里只用 token（`bg-page`、`text-muted`、`border-line`……），不直接写色号，也不用 Tailwind 的原始色（`stone-500` 之类）和 `dark:` 变体。** 这样换配色只改一处，明暗两版也由同一个名字承担。

### 基础色

| token | Tailwind 类名示例 | 亮色 | 暗色 | 用在哪里 |
| --- | --- | --- | --- | --- |
| `--color-page` | `bg-page` | `#faf9fc` | `#16141c` | 页面背景 |
| `--color-surface` | `bg-surface` | `#f3f1f7` | `#1f1c28` | 代码块、行内代码、标签的底色 |
| `--color-line` | `border-line` | `#e4e0ec` | `#322e3f` | 边框、分隔线 |
| `--color-muted` | `text-muted` | `#6e6a7c` | `#8f8a9f` | 次要文字：日期、摘要、目录、页脚、GitHub 图标 |
| `--color-body` | `text-body` | `#2b2833` | `#cfcbd9` | 正文 |
| `--color-heading` | `text-heading` | `#17151c` | `#eceaf2` | 标题、站名、粗体 |
| `--color-accent` | `text-accent` | `#7658c8` | `#c9bcf5` | 强调色：链接、悬停、焦点环 |
| `--color-deco` | `text-deco` | `#c8baf2` | `#9483d6` | 装饰紫：星点、列表圆点、引用竖线、选中文本底色 |

亮色下的强调色已经浅到接近下限：再浅，压在次级表面上的对比度就会低于 4.5:1。想让页面看起来更「淡紫」，应该调装饰紫或暗色那一组，而不是继续调浅它。

强调色和装饰紫要分开用：**装饰紫的对比度不够承载文字**（亮色下对页面背景只有 1.70:1），任何需要被读的东西都用强调色。

### 质感

底色保持克制的紫灰，质感靠两处很轻的处理，都以不影响阅读为前提：

- **纸张颗粒**：整个视口上固定铺一层细噪点（内联 SVG 生成，不请求图片），叠在页面底色上；代码块、提示块这些次级表面盖在它上面，自己是平的。亮色直接以 4.5% 的透明度叠加，暗色用 soft-light 混合、35% 浓度。实测亮度起伏约 ±1（亮色）和 ±1.5（暗色，满值 255），要凑近才看得出。
- **次级表面的厚度**：代码块和提示块顶边有一线高光，底下一层很浅的投影，让它们像一张压在纸上的卡片，而不是一块平涂的色块。

颗粒会让页面底色的实际亮度略有偏移：亮色下每个通道约暗 1.5，暗色下约亮 4（相当于从 `#16141c` 变成接近 `#1a1820`）。下面的对比度是按 token 的标称色值算的，没有计入这个偏移。

试过又放弃的做法：把背景改成饱和度更高的紫，并在页面顶部加两团紫色光晕。看起来更活泼，但大面积的彩色底不耐读，已撤回。

### 提示块（Callout）颜色

| token | 亮色 | 暗色 | 对应的 Callout 类型 |
| --- | --- | --- | --- |
| `--color-note` | `#4a6fa5` | `#8fb0e0` | note 及未列出的类型（默认） |
| `--color-tip` | `#33725f` | `#86c9b4` | tip、hint、success |
| `--color-warning` | `#8a6220` | `#dcb679` | warning、caution、question |
| `--color-danger` | `#b04a5a` | `#e69aa6` | danger、error、bug |
| `--color-important` | `#a14d8c` | `#dc9ccb` | important、example |
| （用 `--color-muted`） | | | quote |

这组颜色整体压低了饱和度，免得在冷静的底色上太跳。important 用梅红而不是紫色，避免被当成链接。提示块的底色是对应颜色以 9% 混入透明。

### 对比度

按 WCAG 2 的公式计算，正文类文字的要求是不低于 4.5:1。

| 前景 | 背景 | 亮色 | 暗色 |
| --- | --- | --- | --- |
| 正文 | 页面 | 13.77 | 11.47 |
| 标题 | 页面 | 17.25 | 15.31 |
| 次要文字 | 页面 | 4.99 | 5.48 |
| 强调色 | 页面 | 5.00 | 10.42 |
| 正文 | 次级表面 | 12.89 | 10.52 |
| 次要文字 | 次级表面 | 4.67 | 5.02 |
| 强调色 | 次级表面 | 4.68 | 9.56 |
| Note | 页面 | 4.87 | 8.21 |
| Tip | 页面 | 5.39 | 9.58 |
| Warning | 页面 | 5.20 | 9.57 |
| Danger | 页面 | 5.04 | 8.29 |
| Important | 页面 | 5.06 | 8.39 |
| 装饰紫（不承载文字） | 页面 | 1.70 | 5.63 |

三点没有覆盖到：颗粒带来的底色偏移（见上文「质感」）；提示块标题实际压在自己 9% 的浅色底上，对比度会比表里对页面背景的数值略低；代码高亮各个 token 的颜色来自 Shiki 的 GitHub 主题，在次级表面上的对比度没有逐一计算。

改色值后要重新算一遍。`design/preview.html` 里的「对比度实测」表会按页面上的实际颜色实时计算，可以先在那里试。

### 代码高亮

Shiki 双主题：亮色 `github-light`、暗色 `github-dark`（在 `astro.config.mjs` 里配置）。token 颜色用主题自带的，**底色不用主题自带的**，统一成 `--color-surface` 加一圈 `--color-line` 边框，让代码块和页面是同一个色温。

## 3．字体

| 用途 | token | 字体 | 来源 |
| --- | --- | --- | --- |
| 正文、界面文字 | `--font-body`（`font-body`） | 霞鹜文楷屏幕阅读版（LXGW WenKai Screen），后备为系统楷体、系统黑体 | npm 包 `lxgw-wenkai-screen-web`，随站点一起部署 |
| 标题、站名 | `--font-serif`（`font-serif`） | 西文用系统衬线体（Iowan Old Style、Palatino、Georgia），中文用思源宋体（Noto Serif SC）600 | npm 包 `@fontsource/noto-serif-sc`，随站点一起部署 |
| 代码 | `--font-mono`（`font-mono`） | 系统等宽字体 | 系统自带 |

- 两款中文字体都按 `unicode-range` 切成上百个分片，浏览器只下载页面上实际用到的字所在的分片；字体没到时先显示后备字体（`font-display: swap`）。两份字体样式表在 `src/layouts/Base.astro` 里引入，作为单独的文件放在 `<body>` 末尾，不并进主样式表：它们的 `@font-face` 列表有三百多 KB，并进去会挡住首屏渲染。
- 霞鹜文楷字面偏小，所以根字号是 106.25%（17px），全站按这个比例放大。
- 霞鹜文楷的分片包只有常规字重，正文里的粗体由浏览器合成。标题因此另配了有真实 600 字重的宋体，只加载 600 这一个字重——标题一律用 `font-semibold`，不要用别的字重。
- 站名按 logo 的字标样式排：衬线体、全小写、字距 0.32em，前面一颗装饰紫的星。

## 4．角色与图片

站点的形象是一个黑发、紫色挑染、头戴黑色蝴蝶结的猫娘角色。所有图片都在仓库根目录的 `pic/` 里：

| 文件 | 内容 | 用在哪里 |
| --- | --- | --- |
| `pic/original/character-sheet.jpg` | 角色设定图原图（1280×720） | 不直接用于站点，是下面三张图的来源 |
| `pic/logo.png` | 头像，透明底（421×431） | 首页介绍区（`src/pages/index.astro`） |
| `pic/character.png` | 全身立绘，透明底（421×1355） | 所有页面右下角的看板娘（`src/layouts/Base.astro`） |
| `pic/favicon.svg` | 头像垫浅色圆角底 | 网站图标（`src/layouts/Base.astro`） |
| `pic/cut-character.mjs` | 生成上面三张图的脚本 | `node pic/cut-character.mjs` |

用法上的约定：

- **顶栏不放头像**，站名前只放一颗紫色的星。
- **看板娘**固定在视口右下角，宽 8rem，不响应鼠标，对读屏软件隐藏。只在两侧留白放得下时出现：普通页面要求视口宽度不小于 72rem（1152px），文章页因为正文加目录更宽，要求不小于 88rem（1408px）；更窄的屏幕和打印时不显示。这两个门槛写在 `src/layouts/Base.astro` 里，是按「内容宽度 + 两侧各放得下看板娘」算出来的，改页面宽度或看板娘尺寸时要重算（媒体查询里的 rem 按 16px 算，页面里的 rem 是 17px）。
- **暗色模式**下黑发黑裙会融进背景，所以带 `figure` 类的图片会压一点亮度，并沿轮廓描一圈淡紫色的光。新加的角色图都应带上 `figure` 类。
- 页面里的头像和立绘通过 Astro 的 `<Image>` 引入，构建时会转成 WebP 并按屏幕密度生成多个尺寸。
- 网站图标垫了浅色底而不是透明，是为了在深色的浏览器标签栏上也看得清墨线。

**分辨率的限制**：设定图只有 1280×720，头像原始宽度约 180 像素、全身像约 230 像素，都是放大后再抠图的，边缘偏软。看板娘的显示尺寸小，问题不大；首页头像在高分屏上不够锐利。拿到高清原图后，替换 `pic/original/character-sheet.jpg`，按新图的像素位置调整脚本里的 `CROPS`，重新运行即可。

## 5．各处的样式约定

- **页面宽度**：普通页面 `max-w-3xl`，文章页 `max-w-5xl`（正文 + 右侧目录）。
- **顶栏**：左边是星点加站名（点击回首页），右边只有一个 GitHub 图标，指向 `src/site.config.ts` 里的 `github` 地址、在新标签页打开。没有导航菜单：站点只有首页（列出全部文章）和文章详情页两种页面。
- **顶栏与页脚**：各有一条 `border-line` 的细线与正文分开。
- **链接**：强调色，1px 下划线，悬停时加粗到 2px。
- **标签**：次级表面底色的胶囊，次要文字色。只在文章详情页显示，是纯文字，不能点击。
- **引用**：左侧 3px 装饰紫竖线，次要文字色，不用斜体和引号。
- **分隔线**（Markdown 的 `---`）：不画线，居中放一颗装饰紫的星。
- **列表圆点**：装饰紫。
- **选中的文字**：装饰紫 45% 透明度的底色。
- **键盘焦点**：2px 强调色外框。

正文排版用 `@tailwindcss/typography` 的 `prose` 类，它的各个颜色变量（`--tw-prose-*`）在 `global.css` 里统一指向上面的 token，所以页面上只写 `prose`，不要再加 `prose-stone`、`dark:prose-invert` 之类的配色类。

## 6．动效

目标是「灵动但不打扰阅读」：动作幅度小、速度慢，正文区域里除了链接下划线不放任何动效。全部用 CSS 实现，没有脚本。

| 位置 | 效果 | 时长 |
| --- | --- | --- |
| 站内跳转 | 新旧页面交叉淡入淡出（浏览器原生的跨页面视图过渡） | 浏览器默认 |
| 页面内容 | 进入时自下而上浮现 0.6rem 并淡入 | 0.55 秒，一次 |
| 看板娘 | 上下缓慢浮动 0.45rem | 6 秒一个来回，循环 |
| 顶栏和页脚的星点 | 缓慢闪烁（变淡、缩小再恢复） | 4.5 秒一次，循环 |
| 站名 | 悬停时前面的星转半圈 | 0.7 秒 |
| GitHub 图标 | 悬停时变成标题色，略放大并微微倾斜 | 0.3 秒 |
| 首页头像 | 悬停时略放大并微微倾斜 | 0.5 秒 |
| 文章列表的条目 | 悬停或键盘聚焦时，左侧浮出一颗星，标题和摘要右移 0.375rem，标题变强调色 | 0.3 秒 |
| 首页介绍区（头像与简介） | 向上滚出视口的过程中逐渐淡出、上移 1.5rem、缩到 96% | 跟随滚动 |
| 文章列表的条目 | 从视口底部滚进来时逐条浮现；一开始就在视口里的不动 | 跟随滚动 |
| 目录链接 | 悬停时右移并变强调色 | 0.2 秒 |
| 正文里的链接 | 悬停时下划线加粗并下移 | 0.2 秒 |

约定：

- **尊重「减弱动态效果」**：读者在系统里开了这个选项时，所有位移、缩放、旋转和循环动画都不播放，只保留颜色变化和淡入。循环动画和进入动画写在 `global.css` 的 `prefers-reduced-motion: no-preference` 里，悬停位移用 Tailwind 的 `motion-safe:` 前缀。新加的动效也照此办理。
- 循环播放的只有看板娘和星点两处，不要再加。
- 跨页面视图过渡在不支持的浏览器（目前是 Firefox）里没有效果，页面照常直接切换。
- 两种跟随滚动的效果用浏览器原生的滚动驱动动画（`animation-timeline: view()`），写在 `@supports` 里。不支持的浏览器（目前是 Firefox）里介绍区照常滚走、条目直接显示，内容不受影响。
- 首页的文章是构建时一次性全部写进页面的，「滚动时逐条浮现」只是视觉效果，不是按需请求数据。

## 7．怎么改

| 想改什么 | 改哪里 |
| --- | --- |
| 某个颜色 | `src/styles/global.css` 的 `@theme`，改完重新核对对比度，并更新本文档第 2 节的表 |
| 字体 | `global.css` 的 `--font-*`，以及 `src/layouts/Base.astro` 里引入的字体样式表 |
| 代码高亮主题 | `astro.config.mjs` 的 `shikiConfig.themes` |
| 角色图 | 换 `pic/original/` 里的原图，改 `pic/cut-character.mjs` 的 `CROPS`，重新运行脚本 |
| 看板娘的大小、出现的宽度门槛 | `src/layouts/Base.astro` 里看板娘的类名和 `mascotFrom` |
| 动效的幅度和速度 | 循环与进入动画在 `global.css` 的「动效」一节；悬停效果在各组件的类名里 |
| GitHub 地址 | `src/site.config.ts` 的 `github` |
| 先试一套新配色再决定 | `design/preview.html`，它不参与构建，可以随便改 |

`design/preview.html` 是定稿前的探索稿，保留作试验场。它和正式站点**不会自动同步**：token 的名字不同，字体从 CDN 加载，排版是手写的近似。以 `global.css` 和本文档为准。
